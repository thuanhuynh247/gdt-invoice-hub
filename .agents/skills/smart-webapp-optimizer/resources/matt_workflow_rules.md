# Matt Pocock Workflow & Architecture Rules

Quy chuẩn định hình luồng phát triển, quản lý ngữ cảnh và kiểm thử đạn nối đạn theo kiến trúc Matt Pocock.

## 1. Luồng chính: Ý tưởng ➔ Thực thi (Main Flow)

```text
Idea / Request ➔ Grill-with-docs ➔ Prototype Detour (Nêu cần UI) ➔ To-Spec ➔ To-Tickets ➔ TDD Implement ➔ Code Review
```

1. **`grill-with-docs`**: Phỏng vấn làm rõ yêu cầu dựa trên tài liệu dự án (`CONTEXT.md`, `AGENTS.md`, `implementation_plan.md`).
2. **`to-spec` & `to-tickets`**: Chuyển cuộc phỏng vấn thành bản đặc tả kỹ thuật và chia nhỏ thành các ticket tracer-bullet cô lập trong `.scratch/<feature>/issues/`.
3. **`tdd` (Red-Green-Refactor)**: Viết test trước hoặc chạy test cô lập phát hiện lỗi trước khi sửa mã nguồn.
4. **`code-review`**: Đánh giá sự thay đổi dựa trên 2 trục (Standards + Spec) trước khi commit.

## 2. Quản lý Ngữ cảnh (Context Hygiene & Smart Zone)
- Giữ cuộc phỏng vấn và lập ticket trong **1 cửa sổ ngữ cảnh liên tục** (~150k tokens smart zone).
- Nếu ngữ cảnh sắp vượt Smart Zone, thực hiện `/compact` tại các mốc Phase Boundary trước khi tiếp tục.

## 3. Quản lý Ranh giới Pha (Phase Boundaries)
Tại ranh giới giữa 2 pha công việc (Grilling ➔ Implement ➔ Review):
- **Continue**: Tiếp tục nếu context còn sạch.
- **Subagent**: Ủy quyền tác nhân con xử lý công việc cô lập.
- **`/compact`**: Nén ngữ cảnh và mở session mới khi công việc kéo dài.
